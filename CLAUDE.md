# CLAUDE.md

Подсказки для Claude Code в этом репозитории.

## Что это

Учебный проект: руководство «LINQ под капотом» (`docs/LINQ_Pod_Kapotom.md`), собственная реализация `MyLinq` (`src/CoreLinq`), тесты `MyLinq` (`tests/CoreLinq.Tests`) и испытания EF Core 10 на SQLite (`tests/CoreLinq.EfCore.Experiments`). Подробности — в `README.md`.

## Команды

```bash
dotnet build CoreLinq.sln
dotnet test tests/CoreLinq.Tests
dotnet test tests/CoreLinq.EfCore.Experiments --logger "console;verbosity=detailed"
```

`CoreLinq.Tests` собирается под net8.0 и net10.0, нужны оба SDK. Проект с EF Core — только net10.0.

## Правила

- **Язык.** Руководство, комментарии и README — по-русски. Идентификаторы и имена тестов — по-английски.
- **Руководство и код — одно целое.** `src/CoreLinq/MyLinq.cs` — дословная копия блока кода из Части 13 руководства. Менять их можно только вместе, `GuideSyncTests` следит за совпадением.
- **Руководство важнее подгонки.** Если тест показывает, что утверждение руководства неверно (особенно в EF-испытаниях), исправлять надо руководство, а не тест. После правки обновить и примечание «Версии и проверка» в начале руководства.
- **Стиль C#** берётся из `.editorconfig`: явные типы вместо `var` (кроме анонимных типов), `new()` с целевым типом, фигурные скобки всегда, namespace с блоком, `using` снаружи namespace. Файлы `.cs` — UTF-8 с BOM, перевод строки LF.
- **EF Core.** Для проверок трансляции использовать SQLite, а не провайдер `InMemory`: он не переводит LINQ в SQL, и тест на нём ничего не доказывает. Не полагаться на порядок строк без `ORDER BY`. Не использовать `decimal` в сортировке и агрегатах (SQLite их не поддерживает).
- **Версии пакетов.** Пакеты EF Core зафиксированы на 10.0.13 (на ней сняты примеры SQL в руководстве). Обновляй версию осознанно: сначала посмотри, не поменялись ли SQL и тексты ошибок, на которые опираются тесты и руководство.
- **Коммиты.** Работать в ветке, не в `main`. В `main` изменения попадают через pull request после зелёного CI.
